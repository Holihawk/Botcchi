# Botcchi

Agent 原生的 AI 助手：独立 Agent Core 统一处理 QQ（OneBot v11）与 Web 对话，支持流式输出、工具调用、MCP、短期/长期记忆、多人格和群聊触发策略。

## 快速开始

要求：Python 3.12+、[uv](https://docs.astral.sh/uv/)。构建 WebUI 另需 Node.js 20+；PostgreSQL 17/18 与 Redis 7 可选但推荐。

```bash
uv sync
cp config.example.yaml config.yaml       # 至少配置一个模型 provider 的 api_keys
docker compose -f docker/compose.yaml up -d # 可选：PostgreSQL + Redis
uv run botcchi chat                       # 终端验证模型与人格
uv run botcchi serve                      # 启动服务
```

WebUI 构建（首次或前端更新后执行）：

```bash
cd web && npm install && npm run build
```

服务地址：

- WebUI/API：`http://localhost:8300/`
- 健康检查：`GET /api/health`
- OneBot 反向 WebSocket：`ws://localhost:8300/onebot/v11/ws`

NapCat 或 Lagrange.OneBot 作为 WebSocket 客户端连接上述地址；`onebot.access_token` 需与协议端一致。详细示例见 `config.example.yaml`。

## 配置与人格

默认读取工作目录的 `config.yaml`，也可使用 `uv run botcchi serve -c <path>` 或 `BOTCCHI_CONFIG` 指定。配置含密钥，不要提交；WebUI 保存 Provider 后会写入 `data/providers.yaml`（已忽略）。

主要配置段：

- `server`、`onebot`：监听地址、端口、反向 WS 路径和权限。
- `trigger`：私聊响应、群聊随机插话、唤醒词、冷却、复读机和群窗口。
- `database`、`redis`、`memory`、`summary`、`social`：持久化、记忆、群总结和社交经济功能。
- `providers`：OpenAI 兼容模型服务，可配置多 Provider、多 Key 轮换和 `fallback_models` 降级链。
- `mcp_servers`：stdio 或 streamable HTTP 外部工具服务器。
- `weather`、`imagegen`、`websearch`、`linkparse` 等：按需启用的联网工具。

`data/assistants/*.yaml` 定义人格，可在 WebUI 编辑并热生效，也可直接修改后重启。支持 `model`、`fallback_models`、`tools`、`policy`、`prompt_file` 等字段；未指定 prompt 时自动加载同名 `.prompt.md`。同一会话可用 `切换人格 <name>` 更换人格。

## 架构

```text
┌──────────────────────────────┐       REST + SSE       ┌─────────────────────┐
│ WebUI（React）                │◄──────────────────────►│ FastAPI API         │
│ 对话 / 人格 / 记忆 / 统计     │                        └──────────┬──────────┘
└──────────────────────────────┘                                   │
                                                                    ▼
┌────────────────────────────────────────────────────────────────────────────┐
│ Agent Core                                                                  │
│ Agent Loop（流式、多轮工具） │ Context/Memory │ Provider（多服务商/key轮换） │
│ Tool Registry（内置工具、MCP）│ Trigger Engine │ Assistant / Social          │
└───────────────────────────────┬────────────────────────────────────────────┘
                                │ Channel 抽象
                 ┌──────────────┴──────────────┐
                 ▼                             ▼
       OneBot v11 Adapter                Web Chat Adapter
       反向 WebSocket                    浏览器会话
                 │                             │
          NapCat / Lagrange                 WebUI

        PostgreSQL（会话、记忆、社交） + Redis（群窗口/缓存）
```

核心与渠道无关：QQ 群、私聊和网页共享 Agent Loop、人格、工具和记忆；伪人模式只是群渠道的触发策略。

## QQ 与 WebUI

QQ 使用 OneBot v11 反向连接。NapCat 在网络配置中添加：

```text
ws://<Botcchi主机>:8300/onebot/v11/ws
```

Lagrange 在 `Implementations` 中使用 `ReverseWebSocket`，端口 `8300`、后缀 `/onebot/v11/ws`。

WebUI 提供：流式对话、多会话、人格编辑、Provider/模型管理、会话浏览、长期记忆管理、统计和定时任务。API 无鉴权，仅限本机或可信内网；公网访问必须通过 SSH 隧道或带认证的反向代理。

前端开发：`cd web && npm run dev`（默认 `5173`，自动代理 `/api`）。

## QQ 指令

指令直接匹配，不经过 LLM。尖括号表示必填参数，方括号表示可选参数；`@某人` 也可用 QQ 号替代。

### 聊天与会话

| 指令 | 权限 | 作用 |
|---|---|---|
| `帮助` / `菜单` / `help` | 所有人 | 查看按当前配置过滤的功能菜单；`帮助 <编号或名称>` 查看详情 |
| `reset` | 私聊所有人；群内管理 | 清空当前会话短期上下文，不删除长期记忆 |
| `清除记忆` / `清空记忆` | 私聊清自己；群内超管 | 删除对应用户或群的长期记忆 |
| `人格列表` | 所有人 | 列出可用人格，`*` 标记当前人格 |
| `切换人格 <name>` | 私聊所有人；群内管理 | 持久化切换当前会话人格 |
| （自然语言） | 所有人 | “提醒我”“记住这件事”“点首歌”“戳戳我”等由已启用工具处理 |

### 实用功能

| 指令 | 权限 | 作用 |
|---|---|---|
| `消息总结 [数量] [主题]` | 群内所有人 | 总结最近消息（默认 200，最多 1000），可按主题聚焦 |
| `总结定时 <小时> [最少消息数]` / `总结定时取消` | 群管理 | 设置或取消每日群总结 |
| `孤独日报` | 所有人 | 生成当日新闻聚合日报（按日缓存） |
| `日报定时 <小时>` / `日报定时取消` | 群管理 | 设置或取消日报推送 |
| `天气 <城市>` / `<城市>天气` | 所有人 | 实况、空气质量、预警和 3 日预报 |
| `画图 <描述>` / `生图 <描述>` | 所有人 | AI 生图；`画图 竖图/横图/高清 <描述>` 选择预设，带图或引用图片可改图；`画图 帮助` 查看用法 |
| （发送分享链接） | 所有人 | 自动解析 B 站、抖音、微博、小红书、快手、AcFun、网易云等链接，输出摘要并按限额转发媒体 |

### 社交与小游戏

| 指令 | 权限 | 作用 |
|---|---|---|
| `签到` | 所有人 | 每日获得好感度和金币，连续签到有加成；卡片每天最多发送一次 |
| `我的信息` / `好感度` / `我的金币` | 所有人 | 查看个人卡片、等级、余额、排名和连签 |
| `好感度排行` | 所有人 | 查看全局好感度 Top 10 |
| `商店` | 所有人 | 查看挂件和消耗品货架 |
| `购买 <商品> [数量]` | 所有人 | 使用金币购买商品（可叠加商品最多 99 件） |
| `佩戴 <挂件>` / `装备 <挂件>` / `取下挂件` | 所有人 | 管理头像挂件 |
| `我的背包` / `背包` | 所有人 | 查看物品与金币余额 |
| `决斗@某人` / `@某人 决斗` | 群内所有人 | 发起 1v1 轮盘决斗；对方 45 秒内发送 `接受` 或 `拒绝` |
| `决斗` | 群内所有人 | 开启或加入多人桌，最多 6 人；发起者用 `开始` 开局 |
| `选 <道具>` | 决斗玩家 | 开局前选择糖、手铐、透镜或延长管 |
| `打自己` / `打对面` / `打@某人` | 当前回合玩家 | 开枪 |
| `用 <道具>` | 当前回合玩家 | 使用道具；手铐需指定目标 |
| `24点` | 群内所有人 | 开启或加入抢答桌，最多 8 人；`开始` 后直接发送算式，每轮最多 3 次 |
| `blackjack` | 群内所有人 | 开启对庄 Blackjack（最多 8 人，单人可玩）；`开始`、`拿牌`、`停牌` |
| `blackjack 暗牌` | 群内所有人 | 私聊发牌的暗牌赛制（至少 2 人，需能私聊 bot） |
| `今日小猪` | 所有人 | 抽取当天固定的小猪占卜卡 |
| `随机小猪 [数量]` / `找猪 <关键词>` | 所有人 | 从 PigHub 获取随机或关键词猪图 |
| `赞我` / `点赞` / `给我点赞` | 好友 | 给 bot 主人的资料卡点赞；回赞会奖励金币和好感度 |

### 群管理

| 指令 | 权限 | 作用 |
|---|---|---|
| `我的权限` / `权限 @某人` | 所有人 | 查看生效权限等级 |
| `功能列表` | 群内所有人 | 查看本群功能开关 |
| `封禁 @某人 [时长] [原因]` / `解封 @某人` | 群管理 | 用户封禁；时长支持 `3天`、`12小时`、`30分钟`，不填为永久 |
| `授权 @某人 <等级>` / `取消授权 @某人` | 群管理 | 授予或撤销数值权限等级 |
| `关闭功能 <功能>` / `开启功能 <功能>` | 群管理 | 按群开关闲聊、签到、游戏、天气、绘图、解析等功能 |
| `休眠` / `唤醒` | 群管理 | 暂停或恢复本群普通响应 |
| `查看欢迎语` | 群内所有人 | 查看当前欢迎语 |
| `设置欢迎语 <文案>` | 群管理 | 自定义进群欢迎语；填 `默认` 恢复 |
| `设置退群提示 <文案>` | 群管理 | 支持 `{名字}`、`{操作者}`；填 `默认` 恢复 |
| 回复 bot 消息后发送 `撤回` | 超管 | 撤回 bot 自己发送的消息 |

### 超管

| 指令 | 作用 |
|---|---|
| `查看请求` / `同意请求 <编号>` / `拒绝请求 <编号>` | 审批好友申请和入群邀请；bot 不自动同意 |
| `忽略请求 <编号>` / `清空请求` | 清理待办，不调用协议端审批 |
| `广播 <内容>` / 引用消息后 `广播` | 向所有未封禁、未休眠群发送消息 |
| `广播撤回` | 撤回最近一次广播（重启后失效） |
| `金币设置 <数量> @用户` | 直接调整金币并记录流水 |
| `好感度设置 <数值> @用户` | 直接调整好感度 |
| `好友列表` / `群组列表` | 查看 bot 的好友或群组 |
| `退群 <群号>` | 退出指定群 |

触发规则：@机器人、包含 `trigger.wake_words` 的消息和私聊默认必回；群内其他消息按 `group_reply_rate` 概率进入伪人模式。伪人插话使用群窗口，但不携带用户上下文工具。

## 架构与状态

核心采用 Python + FastAPI + pydantic + httpx 的轻量 Agent Loop：Channel 层（OneBot/Web）与 Agent Core 解耦；Core 包含 Provider、Assistant、Memory、Tool Registry、Trigger Engine、Social 和 MCP 客户端。WebUI 通过 REST + SSE 通信，QQ 回复按人格策略聚合、分段发送。

当前重构已完成 M1（Agent/Provider/OneBot/人格）、M2（触发、持久化、记忆、多人格）和 M3（WebUI）；M4 生态已落地群总结、日报、提醒、天气、绘图、链接解析、签到/好感度/金币、小游戏、权限/群管理、帮助和统计等。旧版数据不迁移，旧功能中校园电费、校园地图、响应时段守卫及部分危险管理操作暂不实现。

## 数据与运行

无 `database.url` 时会话和人格绑定使用内存，重启丢失且长期记忆不可用；无 Redis 时群聊窗口使用进程内实现。生产环境建议启用 PostgreSQL + Redis，并持久化 `data/`。定时总结、日报和提醒按 Asia/Shanghai 调度。

## 安全

不要把 `config.yaml`、`data/providers.yaml` 或包含密钥的日志提交到仓库。MCP、联网解析和图片生成均由配置控制，外部服务不可用时相关功能会降级，不影响核心对话服务。
